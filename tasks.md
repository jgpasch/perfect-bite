## Quantities: auto-increment, usual unit, and editing amounts (spec 4.2, 4.4)

Goal: every item can carry an amount in any unit (count, weight, volume, package), and the app manages it end to end. Most of the base already exists: `parseQuantity` reads `2 lbs chicken thighs`, each add is a `list_item_contributions` row with its own `quantity`/`unit`, `summarizeAmounts` totals them, `ItemRow` shows the total on the right, and the edit sheet has a free-text Amount field. These tasks change three things:

- **Adding the same item twice counts up.** Today `milk` + `milk` reads `1 + 1`. It should read `2`. An add with no amount counts as one.
- **Each ingredient gets a usual unit.** A new household history table, `ingredient_unit_usage`, counts the units each ingredient is bought in. An add with no amount then counts as one of that unit, so `1 gal milk` + `milk` reads `2 gal`.
- **Amounts can be changed without typing.** The edit sheet gets a − / + stepper and a unit picker.

Amounts with no quantity stay stored as null (the user didn't say an amount). The "counts as one" rule is applied only when totals are computed. A lone add with no amount still shows no amount on its row.
