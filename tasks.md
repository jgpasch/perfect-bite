- [x] Recipe collections, data (no spec section yet: this task's text is the spec; mockups `docs/design/recipe-collections/`). A collection is a named set of recipes owned by a household, shared by every member, and a recipe can be in any number of them. Collections sit beside tags and Saved and don't replace them: tags stay the fixed vocabulary the AI fills, and Favorites (per person) and Want to try (a status) stay as they are. Supabase migration: `recipe_collections` (`id`, `household_id`, `name` text 1–40 chars trimmed, `created_by` set by the server, `created_at`, `updated_at`, `deleted_at`, `field_clock`) and `recipe_collection_recipes` (`collection_id`, `recipe_id`, `household_id`, `added_at`, `deleted_at`, `field_clock`, primary key `(collection_id, recipe_id)`, the recipe and collection in the same household). Both are household data through `apply_mutations` with field-level LWW (`name` and `deleted_at` on collections; `deleted_at` on memberships, keyed `{ collection_id, recipe_id }` like `recipe_favorites`), readable and writable by every member, with RLS and pgTAP tests (a non-member can't read or write; a membership can't point across households). Names are unique per household among live collections, compared ignoring case and accents; the app checks before writing, and if two devices race, both survive (no server constraint). Deleting a collection soft-deletes it and leaves its memberships (they're ignored while it's deleted); deleting a recipe leaves its memberships, so restoring it brings them back. Local Drizzle migration for both tables, push and pull in `src/sync/` like favorites, and `wipeLocalData` covers them. `src/features/recipes/collections.ts`: `createCollection(householdId, name)`, `renameCollection`, `deleteCollection`, `setRecipeInCollection(recipeId, collectionId, on)`, `addRecipesToCollection(collectionId, recipeIds)` (one transaction, skips ones already in), and live queries for a household's collections (A–Z, each with its live-recipe count and its first four recipes' photos for the cover) and a recipe's collections. Free on every plan, no limit. Unit tests for create (including a duplicate name refused), rename, delete, add and remove, batch add, the counts ignoring deleted recipes, and sync round-trips.
