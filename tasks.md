## Debugging and flagging AI calls

Goal: see why AI calls fail, and find people misusing the AI, e.g. a fake recipe written to get an explicit AI photo, with who did it and exactly what we sent the model. `public.ai_calls` already has one row per model attempt by `runAiTask`, with its `status`, `error`, instructions and prompt, but no user id (by design until now), a provider error keeps only the SDK's message, the AI photo's image call (`generateImage`, OpenAI Images) isn't recorded at all, and the portal shows only counts. A photo description that answers `isFood: false` is an `ok` call, so it has to be flagged on purpose, not found among the failures. The spec changes with this: `ai_calls` now records who made each call, and admins can read any call's instructions, prompt and response in the portal (each read is audited) and see the AI photos that were made, since a harmful photo the image model allowed is never flagged. Rows still expire after 30 days, except flagged calls and the calls linked to them, kept 180 days. Emailing the owner about flags (Resend) comes later; not in these tasks.
