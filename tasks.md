## Suggest tags with AI

Goal: a user who made a recipe by hand (New recipe, or from list items) can ask the AI to tag it instead of picking every tag themselves. Imports are already tagged by `import-recipe` (4.14, 6.6); this is the same tagging, run on demand on a recipe that's already saved. The AI only *suggests*: the suggestion fills the Tags sheet's pills and the user checks them and taps Save, so nothing is written without a person seeing it, and the AI never overwrites tags behind anyone's back. Tags only, not total time: a hand-made recipe has no steps to work a time out from. It runs on the recipe's name, notes and live ingredients as the device has them (local-first: the recipe may not have synced yet), so the server reads no recipe rows. It's an AI feature, so it's behind a plan feature like the others (4.12): a new key `recipe_tags`, added to **plus** (imports there are already AI-tagged; base and standard don't get it). Mockups: the Tags sheet and the recipe band look as in https://claude.ai/artifact/9KSu3QFwemeYGX669Ddypi (board D); the new controls use the existing `Pill`, `Button` and theme tokens, no new styles. Spec: update 4.12 (the new feature, which plan has it, the entry points it hides), 4.14 (suggesting tags), 5 (the usage tables), and add 6.7 "Tag suggestion" (the LLM boundaries, as 6.6 does for extraction). Don't push to or deploy hosted Supabase; that's done by hand.
