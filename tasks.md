## Drag to reorder in As added

Goal: in As added, the user can drag items into their own order (the order they'll shop, or what matters most) and the list keeps it. The order is a device setting, like the view mode and folded sections (4.6): stored in SQLite `device_settings`, so it survives switching views, leaving the list, and quitting and reopening the app, with nothing on the server and nothing shared with other devices or household members. New items still arrive at the top, as As added promises, and the user can go back to plain As added order at any time. Spec: update 4.6's As added bullet (and the long-press line in 4.1/4.5 that says long-press enters Select mode) to describe all of this. Before touching gestures or Reanimated, read the SDK 57 docs and reuse the Aisle order screen's drag (`src/features/categories/aisle-order-list.tsx`, helpers in `src/features/categories/aisle-order.ts`); no new dependencies.

- [x] Logic: the saved manual order. In `src/features/lists/list-view.ts`: `manualOrderKey(listId)` → `list.<id>.manualOrder`, a `readManualOrder(saved: unknown)` that reads defensively (anything that isn't a list of `{ id: string, at: number }` counts as none; duplicates keep the first), and `applyManualOrder(ordered, saved)` that takes the `orderByNewest` result and returns it in the user's order. Each saved entry is an item id plus the `at` its place was based on when saved (the earliest current contribution's `createdAt`, or the item's own, the same key `orderByNewest` sorts by; export that key as a helper rather than recomputing it). **Rules:** an item whose id is saved and whose current `at` equals the saved `at` goes in its saved place; an item that isn't saved, or whose `at` changed (re-adding a checked item replaces its amounts, 4.4, so it counts as a new add), goes above all saved items, in `orderByNewest` order among themselves; a Combine doesn't change `at`, so the item stays where the user put it; checking then unchecking (no new amounts) puts it back in its saved place. Saved entries for items that aren't showing (checked, deleted, on another device) are ignored but kept, so an unchecked item returns to its place; drop them when the next drop saves the order, except checked items, which stay. `saveManualOrder(listId, visibleIds, items)` builds the entries from the order on screen after a drop (every unchecked item, not just the moved one, so the whole order is pinned) plus kept entries for checked items. `clearManualOrder(listId)`. Unit tests in `src/features/lists/__tests__/list-view.test.ts` for each rule above, including a recipe add (several items sharing one timestamp) landing on top as a block in ingredient order, and garbage in storage.

## Always have (household staples)

Goal: each household keeps a short list of ingredients it always has (water, salt, pepper, olive oil), and adding a recipe to a list leaves those out by default, so the list holds only what actually needs buying. Only recipe adds skip staples: the Add to list sheet (4.5), a recipe picked in the add bar at 1× (4.2), and its **Adjust**. Typing "salt", tapping a chip, Siri and Move to another list always add, since asking for it by name means you ran out. Staples are household data like aisle choices (4.3.2): any member can mark or unmark one, it syncs to everyone in the household, and it never crosses households. The UI calls them **Always have**; the table is `household_staples`. ## Recipe steps, photo and servings: the data
