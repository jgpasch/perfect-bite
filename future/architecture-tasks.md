# Architecture

<!-- Status: ideas. Spec: various. -->

Findings from a read-only review on 2026-10-26 of the Expo app, local data and sync, and Supabase, plus the start of a cross-cutting pass. The bugs, security holes, races and the clearest performance fixes were moved into `tasks.md` on 2026-10-26; what's left here needs a product or design decision first, or is refactoring with no user-visible effect. Plain bullets, grouped by area. Still to review: the admin portal (`admin/`) and the rest of the cross-cutting pass (`modules/`, `plugins/`, `targets/`, `app.json`/`eas.json`, test gaps, duplicated and dead code, deprecated Expo APIs for SDK 57).

## Supabase

- **Security** `supabase/migrations/20261009210000_catalog.sql:76-78` and `20261010150000_realtime.sql:24` — `ingredients_select` is `using (true)` for `authenticated` and the table is in the realtime publication, so every signed-in user can read (and subscribe to) the whole global catalog, including names typed by one household (`household_count = 1`, `status`, `attempts`). Spec 6.5's "`household_count >= 3` so one person's odd entry doesn't leak" is enforced only in the app's autocomplete, not by the server. Fix: expose a view or policy limited to `is_grocery_item and household_count >= 3` plus the names the caller's own households use (`ingredient_households`), or accept and document that the catalog is fully readable.
- **Perf / Spec drift** `supabase/migrations/20261029120000_recipe_photo_storage.sql:17,99-108`, `20261106120000_item_photos.sql:86-92` — comments and spec (docs/spec.md:738,753) speak of "a purge" of deleted rows, but no migration ever hard-deletes soft-deleted `lists`/`list_items`/`recipes`/contributions (nothing matches `deleted_at <`), and the photo-deletion triggers only fire on `photo_path` change or row delete. Tombstones and the photos of soft-deleted items and recipes live until the household is deleted, and every new device's first pull downloads every tombstone. Fix: a daily cron job that hard-deletes rows with `deleted_at < now() - interval '30 days'` (children first; the existing `after delete` triggers then queue the photo objects), and a documented tombstone window pull can rely on.
- **Perf** `supabase/migrations/20261010120000_apply_mutations.sql:60-66` and `20261011200000_email_invites.sql:14-18` — `private.applied_counters` gets one row per counter mutation forever and nothing prunes it (no retention job references it), and used/revoked/expired `household_invites` are never deleted. Both grow without bound. Fix: a retention cron for `applied_counters` (rows older than the longest a device may stay offline, e.g. 90 days, since a re-sent HLC that old would compare as stale anyway) and one for closed invites.
- **Perf** `supabase/migrations/20261204120000_user_activity.sql:683-690` with `20261208121500_list_lock_activity_actor.sql:34,89-93` — the activity trigger is `for each row` on 16 tables; every row written by an `apply_mutations` batch does `to_jsonb(old)`/`to_jsonb(new)`, a full-row diff (`activity_changed`) and a correlated `households` name subselect per entry, roughly doubling the per-row cost of sync. Fix: make the trigger statement-level with transition tables, or at least skip the `households` lookup by passing the name once per batch (`set_config`) and precomputing `activity_changed` only for the columns each table's function reads.
- **Duplication** `supabase/migrations/20261011180000_household_aisles.sql`, `20261013180000_recipe_tags.sql`, `20261015120000_household_staples.sql`, `20261020120000_family_combine.sql`, `20261021120000_combine_languages.sql`, `20261023120000_meal_plan.sql`, `20261207120000_household_aisle_order.sql`, `20261208121500_list_lock_activity_actor.sql`, `20261211120000_recipe_favorites.sql`, `20261218100000_recipe_collections.sql:73-396` — the ~320-line `private.apply_mutation` body is pasted in full eleven times, each copy differing by a few lines (a new `when` branch, a check); the per-table rules (key columns, settable fields, server-set columns, referential checks) are interleaved with the LWW engine, so every new synced table re-copies the engine. Fix: split the table rules into a `private.mutation_table_rules(table) returns (key_cols, settable, counter_cols, max_cols)` function (or a config table) plus per-table check hooks, so adding a table no longer redefines the engine; keep the history but make the next migration the refactor.
- **Tests** `supabase/functions/share-import-worker/handler.test.ts:428,452` — `release_share_import` failing with a non-lease error is untested. Fix: a fake store whose `release` rejects once, asserting a 500 that leaves the job leased.

## Local data and sync

- **Layering** `src/sync/push.ts:20-22`, `src/sync/pull.ts:58-61`, `src/sync/realtime.ts:24-25`, `src/sync/purge.ts:34-35` — `src/sync/` imports `@/features/auth/account`, `@/features/categories/{catch-up,categories}`, `@/features/households/member-names`, `@/features/settings/device-settings`, `@/features/lists/{lists,list-view}`, while `features/*` import `@/sync/mutate`: a bidirectional dependency between the sync engine and the feature layer (spec 8.2 places `sync/` beside `db/` and `lib/`, under `features/`). It makes `pull.ts` untestable without the whole feature graph and lets a feature refactor break sync. Fix: move `isOnline`/`startCatchUpTriggers` and `getDeviceSetting` to `src/lib/`, pass `getAccount`, `refreshMemberNames`, `ensureMissingIngredients` and the device-setting keys to the sync starters as hooks/options, and let `purge.ts` take the purge-time device-setting keys from a registry features populate.
- **Spec drift** `src/features/households/households.ts:345,358`, `src/sync/mutate.ts:57`, `docs/spec.md` §7.1 — Spec 7.1 says every write to household data, `households` included, goes through `mutate.ts`; `renameHousehold` and `setCombineLanguages` write `households` with `db.update` directly after the RPC, and `mutate.ts` registers `households` with `unsent: ['combineLanguages']` though only creation is ever pushed (`push.ts:203-210` rejects anything else). Harmless today (pull has no clock for `households` so the server wins), but it leaves `field_clock` on `households` meaningless and two write paths for one table. Fix: either say in §7.1 that `households` changes go through RPC + direct local write, or route them through `updateRows` with a `local-only` option.
- **Duplication** `src/sync/mutate.ts:123-125,165-168`, `src/sync/pull.ts:200-202,277`, `src/sync/apply-writes.ts:45-48` — `columnsOf`, `keyWhere`/key-`where` building and the wire-key/property mapping are reimplemented in three sync modules; `later()` for ISO text exists in `status.ts:61` and `pull.ts:434`; and the "track `online` from `startCatchUpTriggers`" pattern is copied in `push.ts:350-356`, `pull.ts:739-746` and `realtime.ts:175-181`, each with its own `online` variable (so push, pull and realtime can disagree about connectivity). Fix: a `src/sync/table-meta.ts` with `columnsOf`, `keyWhere`, `rowRef`/`refKey` shared by mutate/pull/apply-writes, and one connectivity store (`activity.ts` already holds `online`) that all three read.

## Expo app

- **Layering** `src/features/lists/list-screen.tsx:200-1290` — `ListScreen` is a single ~1,090-line component with 30+ `useState`/`useRef` hooks, 10 effects, three `useFocusEffect` subscriptions and its own `renderEntry`/`renderBlock` closures, importing from eight other features (`auth`, `households`, `categories`, `recipes`, `push`, `siri`, `tabs`, `settings`). Any change re-renders everything and the file is effectively untestable as a unit (it has no test). Fix: split into `useListState(id)` (queries + grouping into `blocks`), `useListToasts(id)` (the four focus-effect toast sources at `:615-716`), `useAddMode`, `useLingering`, and a presentational `ListBlocks` component; move the ⋯ / view-menu toolbar into its own component.
- **Layering / Spec drift** `src/app/recipe/[id]/index.tsx:1-965`, `src/app/list/[id]/item/[itemId].tsx:1-885`, `src/app/(tabs)/recipes/index.tsx:1-879`, `src/app/recipe/[id]/cook.tsx:1-780` — Spec §8.2 puts routes in `src/app/` and logic in `src/features/*`, but these route files import `@/db` / `@/db/live-query` directly (34 route files do), hold a dozen pieces of state and all the write handlers. 134 of 241 UI source files have no test, and none of the 50-odd files in `src/app/` has one, because the logic lives in the route. Fix: for each, move the hooks (queries, derived state, toasts) into `src/features/<feature>/use-<screen>.ts` and the JSX into a `<feature>/<screen>.tsx` component, leaving the route file as the thin wrapper `list/[id]/index.tsx` already is; add RNTL tests for the extracted hooks.
- **Bug** (cross-platform) `src/features/tabs/add-menu.ts:39`, `src/features/meal-plan/slot-actions.ts:329`, `src/features/recipes/photo-import-prompts.ts:12`, `src/features/lists/list-screen.tsx:599`, `src/app/recipe/[id]/index.tsx:285`, `src/app/list/[id]/item/[itemId].tsx:225`, plus `src/app/lists-sheet.tsx`, `src/app/(tabs)/settings/always-have.tsx`, `src/app/(tabs)/settings/households/[id].tsx`, `src/features/lists/add-bar.tsx`, `src/features/recipes/add-sheet.tsx` — `ActionSheetIOS.showActionSheetWithOptions` is called with no `Platform.OS` guard in 11 files (only 9 `Platform` checks exist in the whole app); `Alert.prompt` (iOS-only, flagged `TODO(M9)` in five `prompt-*.ts` files) is also used unguarded at `src/app/recipe/[id]/index.tsx:222`/`:237`/`:248` and `src/app/list/[id]/item/[itemId].tsx:135`; and `src/hooks/use-keyboard-visible.ts:8-9` listens only to `keyboardWillShow/Hide`, which Android never fires, so `AddBar`'s bottom padding (`src/components/add-bar.tsx:58`) is wrong there. Spec line 32 says Android "is not a target, but nothing should rule it out", and `app.json` ships an `android` section; on Android the + long-press menu, Select-mode Delete, slot actions, ingredient quick-add and photo-source prompts silently do nothing. Fix: one `showActionSheet(options)` helper in `src/components/` (ActionSheetIOS on iOS, `Alert.alert` buttons or `@expo/react-native-action-sheet` elsewhere), a `promptText()` wrapper around `Alert.prompt`, and `Platform.select` between `keyboardWill*` and `keyboardDid*` events; route every call site through them.
- **Duplication** `src/features/tabs/add-button.ts:38`, `src/features/lists/move-result.ts:14`, `src/features/lists/recipe-add-result.ts:35`/`:63`, `src/features/auth/delete-account.ts:99`, `src/features/push/receiving.ts:77`, `src/features/recipes/saved-recipe-result.ts:23`, `src/features/recipes/deleted-collection-result.ts:29`, `src/features/recipes/collection-ticks-result.ts:28`, `src/features/households/deleted-household-notice.ts:11` — Ten hand-rolled module-level "mailboxes" (`let pending…; export function takeX(); export function onX(listener)`) pass a result from a closing sheet to the screen underneath, each with its own listener set and each consumed by a copy-pasted `useFocusEffect(() => { show(); return onX(show); })` block (e.g. `list-screen.tsx:615-716`, `recipes/index.tsx:261-275`, `:300-320`). Fix: one generic `createResultChannel<T>()` returning `{ post, take, subscribe, useOnFocus(handler) }` in `src/features/navigation/` (or `src/hooks/`), and replace the ten modules with instances.
- **Tests** `src/features/recipes/recipe-card.tsx` (554 lines), `src/features/meal-plan/week-grid.tsx` (544), `src/features/recipes/imports-card.tsx` (449), `src/features/lists/item-photo.tsx` (436) — the most complex components outside the route files have no test file (the meal-plan logic tests moved to `tasks.md`). Fix: RNTL tests for `RecipeCard`'s menu/quick-add and `ItemPhotoSection`'s upload/offline states.
- **Duplication** `src/features/notifications/notification-host.tsx:170-177`, `src/features/lists/keep-awake.ts:26`, `src/app/(tabs)/settings/notifications.tsx:33-48` — `useAppActive` in the notification host is a line-for-line copy of `useForeground` in keep-awake.ts (`AppState` listener, `state !== 'background'`), and `usePushPermission` adds a third hand-rolled `AppState.addEventListener('change', …)` with its own `cameToForeground` bookkeeping; 10 files subscribe to `AppState` directly. Fix: move `useForeground` to `src/hooks/use-foreground.ts`, add a `useOnForeground(callback)` beside it, and use them in the notification host and the Notifications settings screen.

## Cross-cutting

- **Repo hygiene** `deno.lock` (root), `supabase/functions/*/deno.lock` (14 lock files) — There is a root `deno.lock` with no root `deno.json`, and each of the 13 Edge Function directories plus `_shared/` carries its own `deno.json` + `deno.lock` with pinned `npm:` versions. Three `package.json` scripts pass `--no-lock` and the rest do not, so the root lock is written by whichever Deno script runs next. Fix: one `supabase/functions/deno.json` import map (Supabase supports a shared `import_map.json`/`deno.json` per project) with a single lock file, and `--no-lock` on every root Deno script or none.
