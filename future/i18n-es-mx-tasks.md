# Mexican Spanish

Spanish ships in pieces, but users see none of it until the **Switch on Spanish** section: until then the app's supported languages are English only, and Spanish shows only in a development build with `EXPO_PUBLIC_FORCE_LANGUAGE=es`. Every task before that keeps the English app exactly as it is (the existing tests stay green unchanged).

Before any task that touches `expo-localization` or app config, read the SDK 57 docs: https://docs.expo.dev/versions/v57.0.0/sdk/localization/ and https://docs.expo.dev/guides/localization/ (the plugin's `supportedLocales`, and the `locales` key with `ios.infoPlist.CFBundleAllowMixedLocalizations` for translated permission strings).

## Spanish input

Goal: typing in Spanish works as well as typing in English: amounts and units parse, plurals and accents match, a Mexican starter catalog suggests and sorts names without the AI, and linked names share aisle overrides with their English twin (stage 1 of spec 4.15's linked ingredients).

- [ ] Fold accents in the ingredient key (spec 4.15). `normalizeIngredientName` (`src/shared/ingredient-normalizer.ts`, shared with the Edge Functions) strips diacritics after its NFC step (`limón` → `limon`, `jalapeño` → `jalapeno`, `crème fraîche` → `creme fraiche`); display names keep what was typed. A migration merges every existing key that changes into its folded key across every table that holds an ingredient key (the catalog: keep the categorized row, prefer `seed`; `ingredient_usage` and `ingredient_unit_usage`: sum counts, max `last_used_at`; household overrides: keep the newest; list items, contributions, recipe ingredients: rewrite the key), and the app runs the same merge on its local SQLite once (a backfill marker, like the other one-time backfills). Drop the seed's now-duplicate accented spellings (`jalapeños`, `gruyère`, `tajín`, `sazón`, `rosé`, `café bustelo`...) and regenerate the seed SQL. pgTAP and Jest tests for the merge, including two rows that fold to one in the same household. The user pushes the migration to hosted Supabase (hand them the command).
- [ ] Spanish amounts in the quantity parser (`src/shared/quantity-parser.ts`, spec 4.15): Spanish number words (`un`/`una`/`uno` to `veinte`, `medio`/`media` = 0.5, `media docena`), Spanish unit spellings mapped to the existing units (no new units; `pieza(s)`/`pza(s)` is a plain count), and a `de` right after a unit dropped from the name. `half and half`-style guards: a name that merely starts with a number word and no unit stays a name. Accepted whatever the app's language. Table tests, including `2 tazas de harina`, `1 kilo de jitomate`, `medio kilo de queso oaxaca`, `media docena de huevos`, `3 piezas de aguacate`, `1 manojo de cilantro`, `2 dientes de ajo`, `una lata de chiles chipotles`, and that every English case still passes. Run the `siri-add` Deno tests too.
- [ ] Mexican starter catalog and linked ingredients (spec 4.15, 5). Add `src/shared/seed/ingredients-es.ts` in the shape of `ingredients.ts`, about 400 to 600 names as people in Mexico type them, grouped by category and by default unit as sold in a Mexican supermarket (mostly `kg`, `l`, `count` for piezas). Each entry may name the English seed ingredient it means (`['leche', 'milk']`); link only exact shopping-list equivalents and leave `tomate`, `crema`, `chile`, `queso fresco`, `epazote` and similar unlinked (list your doubtful ones in progress.md for the reviewer). A linked name takes its target's category from the generator; an unlinked one states its own. A migration adds `ingredients.lang` and `ingredients.same_as` (FK, nullable; a check or trigger that a target has no `same_as` of its own), and `scripts/gen-seed-sql.ts` emits both, `lang = 'en'` for the English seed. Add both columns to the device catalog (SQLite schema, catalog pull, spec 7.4). Generate the Spanish `-es` plural list for the normalizer from this file (`limones` → `limon`, `nueces` → `nuez`, `frijoles` → `frijol`), and a test that fails when a generated plural collides with an English seed name or its plural. Update spec 6.2 to mention the Spanish seed. The user pushes the migration (hand them the command).
- [ ] Use the links and the language, stage 1 only (spec 4.15). Household aisle overrides are written and read under the family key (`same_as ?? normalized_name`) in the app (`src/features/categories/categories.ts`, the list items query, the category resolver) and anywhere the server reads them; an existing override on a key that is now linked moves to its family key in a migration. Autocomplete's catalog part ranks names whose `lang` is the app's language first (`src/domain/suggestion-rank.ts`). Nothing else follows links: duplicates, Combine, the tint, usage and usual unit still use the ingredient's own key (tests prove `leche` and `milk` stay two items).
- [ ] Spanish-aware categorizer (spec 6.4, 4.15). New prompt version (`categorize.v3`): names may be English or Spanish (Mexico); Spanish names get the unit they're sold in at a Mexican supermarket. Add about 40 Spanish names to the golden set (`jitomate`, `tomate verde`, `chile serrano`, `epazote`, `queso oaxaca`, `crema`, `tortillas de maíz`, `bolillo`, `jamaica`, `Fabuloso`, two injection names in Spanish). Deno tests with the mock model. NEEDS A MANUAL CHECK: the user runs `yarn ai:eval` against the real model and compares with the last run.
