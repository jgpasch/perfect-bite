## Universal Links for invites

Goal: invite links are `https://<LINK_HOST>/invite/<token>` instead of `perfectbite://invite/<token>`, so they're tappable in every messaging app, open the app when it's installed, and show a helpful web page when it isn't. Universal Links don't depend on the App Store: iOS checks the domain's `apple-app-site-association` file against the app's team and bundle id (`4537GH756L.com.jgp.perfectbite`), so they work in development builds and TestFlight builds today. Until the app is in the App Store, the fallback page points to TestFlight; after release it points to the App Store. Also: an invite link opened while signed out is kept through sign-in (spec 4.7 calls this a follow-up).

**Before starting this section (done by hand, not a task):** pick the domain, replace every `<LINK_HOST>` in this section with it (e.g. `perfectbite.app` or `links.<a domain you own>`), and choose where the static site is hosted (Vercel, Netlify, Cloudflare Pages or GitHub Pages; it must serve `/.well-known/apple-app-site-association` over HTTPS as `application/json` with no redirect). Deploying the site and setting DNS are done by hand. The `perfectbite://` scheme stays, so old links keep working.
